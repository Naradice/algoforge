## 1. 独立性の範囲と限界
- 対象: 保存された予測結果(`scores_*.npz`、`ddm_ens_seed*.npy`、`ddm_mapping.json`)と生データに対する、評価処理の独立検証。
- 対象外: 予測分布の生成(統計モデルのサンプラー、DDM の経路生成)の数値的な正しさ。V3 と V9b ではサンプルの再生成に本番サンプラーを使うため、**サンプラーに共通する不具合は検出できない**。R-10b のビット一致検査はリーク検査であり、サンプラーの正しさの証明ではない。
- 「独立」とは、`f1_common.py`、`f1_analyze.py`、`f1_run.py` の計算関数を import せず、仕様書(`docs/research-f1-statistical-baselines.md`)から別に書いた実装を使うこと。総当たり(O(M²))や素朴なループを許す。
- 本番コードの実装詳細(乱数の呼び出し手順など)を参照する検査(V7a)は、**算術の再現**であり、設計の独立検証ではないと明記して扱う。
- 入力は、保全した生データ(終値系列、ハッシュ c25eb572…)、`scores_*.npz`、`selection.json`、`ddm_mapping.json`、`ddm_ens_seed*.npy`、`leak_test.json`。実行前に `C:\tmp\f1_sha256_58files.txt` とのハッシュ一致を確認する。

## 4. V3 の抽出方法(固定)
- 抽出単位: (期間、h)ごとに 1 つの原点集合を作り、全 14 モデルで共有する(モデル間の対比較を保つ)。セルは 2 期間 × 14 モデル × 4 ホライズンの 112。
- 抽出 seed: `numpy.random.default_rng(20261201)`。抽出の前に、手順を固定したコードのハッシュを記録する。
- 構成(優先順位つき、合計 200 原点/(期間, h)が基本。優先枠が 200 を超える場合は優先枠の全部を採用し、超過を記録):
  1. 期間の先頭 5 原点と末尾 5 原点(有効原点)。
  2. 月次再推定の境界: 各月の先頭 2 原点と、各月の末尾 1 原点。
  3. ギャップ近傍: 5 分超のギャップの直後 2 原点と直前 2 原点。ギャップ数が多い場合は、上記 seed で最大 40 原点まで無作為に選ぶ。
  4. 残りを、有効原点から一様無作為に抽出(重複なし)。
- 抽出された原点 ID(`j`)、seed、各枠の内訳を、再計算の前に JSON として保存し、SHA256 を記録する(結果を見てからの変更を防ぐ)。
- 不一致が見つかった場合は、抽出数を増やす前に原因を調査する。原因の区分: (a) 標本の再生成が元と異なる(状態・決定性の問題)、(b) 同じ標本で別実装の CRPS が本番の CRPS と異なる。そのため V3 では、本番の `fair_crps` を再生成標本に適用した値も併記して区別する(この併記だけ本番関数を使う)。

## 5. V5: モデル選択の検証内容
仕様書の規則を別に実装する。タイブレークの順序 `B1 < B2 < B3 < B4 < B7N < B5 < B6 < B7T < B0` は、コードからではなく仕様書から転記する。
ホライズンごとに次を出力する。
1. 全候補(B0, B1, B2, B3, B4, B5, B6, B7N, B7T の 9 つ)の検証平均 fair CRPS。B8 と B4s は候補外であることの確認。
2. 最小 CRPS のモデルとその値。
3. 最小値の 1.005 倍以内(`≤`)に入った候補の一覧。
4. 複雑さの優先順位に従った最終選択と、その理由。
5. 境界の診断: 閾値のすぐ内側・外側の候補との相対差、および閾値との差が 1e-9 未満の候補があるか(`≤` と `<` の違いで選択が変わるか)。
合格: 選択結果が `selection.json`(B7N, B7N, B7N, B4)と完全一致し、境界の診断で規則の解釈による結果の違いがない。

## 6. V6: DM 検定の照合
- 統計量(t): rtol 1e-9。
- p 値: 本番は `2(1 − cdf(|t|))` で計算するため、|t| が大きいと、倍精度での `1 − cdf` の丸め(1 に近い値の刻みは約 1.1e-16)により、p が 0 または刻みの整数倍になる。この丸めは実装と浮動小数点の精度に依存する数値上の現象で、固定の閾値ではない。したがって p 値は次のとおり照合する。
  - 別実装で、p を対数尺度(`log p`、生存関数の対数)で計算する。
  - 本番の p が丸めの影響を受けない範囲(目安として 1e-12 以上、実際の境界は検証結果に記載)は、rtol 1e-6 で照合。
  - 本番の p が丸めの影響を受けたもの(0 を含む)は、検定統計量の一致を主たる照合とし、別実装の `log p` から、本番の丸め条件(本番が実際に返した値、`1 − cdf` の値と刻み)と矛盾しないことを確認する。
  - 検証結果には、h ごとの |t|、別実装の `log10 p`、本番の `1 − cdf` の実際の値、丸めが起きた境界の |t| を記載する。
- Holm 調整後 p 値: 同じ規則で照合し、丸めの影響を受ける項目は、その旨を明記して扱う。
- 付随事項: 報告書の表で「p=0」と書いたのは、この丸めによる表記であり、厳密な 0 ではない。P1 の報告時に実測値とともに記載する(F1 の判定には影響しない)。

## 7. V7: 同時帯の照合と再検証規則(実行前に固定)
production は週ブロックを「`default_rng(20261117)`、各回 `integers(0, W, W)`(W は全ホライズンの週の総数)」で再標本化し、se_h は Δ* の標準偏差、臨界値 c は max|Δ*−Δ|/se の 95 パーセンタイルとして求める。
- **V7a(算術の再現)**: 同じ seed と手順を別実装で再現し、se_h、c、帯の端点を比較する。許容は rtol 1e-12。これは設計の独立検証ではなく、本番の算術が仕様と本番のコードの記述どおりかの確認であり、V7b の判定の前提になる。数値演算の順序による微小な差が rtol 1e-12 を超えた場合は、F1 の誤りと断定せず、まず再実装側(演算順序、集計の方法)との差を調査し、原因の区分を記録してから判定する。
- **V7b(乱数変動を考慮した照合)**: 別の seed 20 本(固定リスト: 1〜20)で、それぞれ 10,000 回の bootstrap を行い、c と se_h(h=1,4,12,24)の 5 量の各々について平均 m と標準偏差 s を求める。本番の値が `m ± t·s·√(1+1/n)` に入ることを確認する。n = 20、`t = t(1 − 0.01/(2×5), 自由度 19) = 3.5794`(5 量について Bonferroni 補正した、全体で両側 99% の予測区間)。各 seed の 5 量が正規分布に従うという近似に基づき、20 seed では近似の妥当性が限られるため、判定保留を設けている。
  - 実行は、固定した 20 seed の 1 バッチのみ。条件による再試行はしない。
- **追加検証(事前に固定した唯一の再検証)**: V7a が一致し、かつ V7b が区間外のときに限り、seed 21〜120 の 100 本で同じ規則(n = 100、自由度 99、`t = 3.1746`)を適用する。**最初の 20 seed とは混合せず**、独立した追加検証として判定する(最初のバッチの結果は別に記録として残す)。結果に関わらず、これが最後。
- 帯の端点の判定: 本番の端点は、V7a が一致していれば本番の値が算術として正しいことを示すため、V7b の結果と合わせて解釈する。
- 結果の扱い:
  - V7a 一致かつ V7b 区間内: V7 合格。
  - V7a 一致で V7b が区間外(追加検証の後も): V7 は **判定保留**(F1 の分類が V8 で一致していても、自動的に合格とはしない)。監査担当者の判断を仰ぐ。
  - V7a が不一致: **不合格**(算術の不一致として原因を調査する)。

## 8. V9: 被覆率・分位損失・PIT の検証(NPZ の内容に合わせて分割)
- **V9a(集計の照合)**: NPZ の原点別 `hit*`、`ql*` の平均が、`final_result.json` の被覆率・分位損失と一致するかを確認する(rtol 1e-12)。これは**集計の検証であり、各値の算出処理の独立検証ではない**と明記する。
- **V9b(標本の再生成による原点別の再計算)**: §4 の標本について、再生成した標本と V1 の実現値から、別実装で `hit50/80/90/95`、`ql*`、`pit_lo`、`pit_w` を再計算して保存値と比較する。
  - 分位点の定義: 昇順に並べた標本の線形補間(位置 `q·(M−1)`)を別に実装し、仕様書の定義との一致を確認する。
  - `hit`: 完全一致。`pit_lo`、`pit_w`: 完全一致(件数/M)。`ql`: rtol 1e-9 / atol 1e-15。
  - `pit`(乱択を含む)は照合しない(`pit_lo + u·pit_w` の乱数は検証対象外)。
- **V9c(必須)**: DDM の被覆率・分位損失・`pit_lo`・`pit_w` を、保存済みのアンサンブル(`ddm_ens_seed*.npy`)と写像(`ddm_mapping.json`)から**全原点**で再計算し、保存値と比較する。許容は V9b と同じ(`hit`・`pit_lo`・`pit_w` は完全一致、`ql` は rtol 1e-9 / atol 1e-15)。DDM の 3 seed、検証・final の両期間、4 ホライズンを対象とする。P2 の診断の基盤にもなる。
  - 限界: アンサンブルから予測標本を復元する処理(写像によるバケットの割り当てとスケーリング)は本番の実装に依存するため、**その処理に共通する不具合は検出できない**。バケットの割り当ては、ATR の定義とバケット境界を別に実装して照合する(割り当ての独立検証を含める)。
  - 統計モデルについては、全原点の再計算は再スコアリングに相当するため P1 の範囲外。
- 完全に独立に再計算できるのは、V9b の標本と V9c の DDM 全原点に限る。統計モデルのそれ以外の原点の被覆率・分位損失は、保存値の集計の照合にとどまる。

## 9. 合否判定
- **合格**: V1〜V9(V9a、V9b、V9c を含む)のすべてが事前固定した許容範囲内。
- **判定保留**: V7 のみが §7 のとおり不一致(V7a は一致)で、追加検証の後も区間外。監査担当者の判断を仰ぐ。F1 の判定は変更しない。
- **不合格**: 確定した計算上の不一致(V1〜V6、V9a・V9b・V9c のいずれか、または V7a の不一致)、または V8 の分類の不一致が 1 つでもある。不合格時は、不一致の内容(検査 ID、モデル、h、原点、差の大きさ)をそのまま記録し、F1 の結果を黙って書き換えず、F1 側と再計算側のどちらの実装が原因かを切り分け、別の finding として報告する。
