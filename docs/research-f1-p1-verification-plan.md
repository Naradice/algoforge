# F1 (#889) P1: スコア配列の独立再計算 — 検証計画(草案 v0.1、未承認)

位置づけ: F1 の監査補強。新しい予測実験ではなく、F1 の結果(コード db0926f、保全済みの `C:\tmp\f1_run1_db0926f`)の信頼性を、別実装で確認する。
承認前に実行しない。承認は、対象・許容誤差・合否基準を含めて得る。F1 の判定と Study Manager の状態は、この検証の結果を待たず、そのまま固定する。不一致が出た場合の扱いは §5。

## 1. 独立性の定義
- 「独立」とは、`f1_common.py`、`f1_analyze.py`、`f1_run.py` の計算関数を再利用せず、仕様書(`docs/research-f1-statistical-baselines.md`)から別に書いた実装を使うこと。素朴なループや総当たり(O(M²))を許す。
- 入力として許すのは、保全した生データ(終値系列の parquet と、そのハッシュ)、`scores_*.npz`、`selection.json`、`ddm_mapping.json`、`ddm_ens_seed*.npy`、`leak_test.json`。ハッシュは `C:\tmp\f1_sha256_58files.txt` と一致させる。
- 独立再計算では、サンプラー(統計モデルと DDM のサンプル生成)の再実装は対象に含めない。含める場合は P1 ではなく別の課題とする(§6)。

## 2. 検証対象と許容誤差(事前固定)
| ID | 対象 | 方法 | 許容誤差 |
|---|---|---|---|
| V1 | 原点集合と実現値 R_h | 生の終値と時刻から、ギャップ規則(5 分超)、ブロック、前ブロックのリターン、RV>0 の除外を別に実装し、全ホライズンの原点集合と R_h を作る | 原点集合は完全一致。R_h は絶対誤差 1e-15 以内 |
| V2 | 全モデルで原点集合が同一 | `scores_*.npz` の `j` を全モデル・全ホライズンで比較 | 完全一致 |
| V3 | per-origin の fair CRPS | 各(期間、モデル、h)から 200 原点を固定 seed で無作為抽出。保全した状態から本番コードでサンプルを再生成(リーク検査でビット一致が確認済み)し、総当たりの fair CRPS を別に計算して、保存値と比較 | 相対誤差 1e-9 以内 |
| V4 | 平均 CRPS と Δ_h | `scores_final.npz` から別実装で、DDM 3 seed 平均と統計モデルの CRPS、Δ_h を計算 | 相対誤差 1e-12 以内 |
| V5 | モデル選択 | `scores_validation.npz` から、ホライズン別の検証 CRPS 最小(B0〜B7、0.5% 以内は複雑さ順)を別に実装して選ぶ | `selection.json` と完全一致 |
| V6 | DM 検定 | Newey-West の長期分散(仕様のラグ)で DM 統計量と p 値を別実装で計算 | p 値の相対誤差 1e-6 以内(0 に丸められた値は同じく 0) |
| V7 | 同時帯と臨界値 | 週ブロック bootstrap を別の乱数列で実装(10,000 回)。se は仕様どおり | 臨界値は 2.419 ± 0.03、帯の端点は ± 0.05 パーセントポイント以内 |
| V8 | 事前規則による分類 | V4・V7 の帯と ±2% から、分類を別に判定 | 4 ホライズンとも、F1 の分類と一致 |
| V9 | 被覆率と分位損失の集計 | `scores_final.npz` と保存した標本統計から、50/80/90/95% 被覆率と 1/5/95/99% 分位損失を別に集計 | 被覆率は完全一致(カウント)、分位損失は相対誤差 1e-9 以内 |

V3 と V9 のうち、サンプルの再生成を要するものは、保全した状態(月次パラメータ、写像、アンサンブル)から行う。再生成に本番コードを使うことは独立性の限界であり、結果に明記する。

## 3. 合否基準
- 合格: V1〜V9 がすべて許容誤差内。
- 部分合格: V7 のみが許容を外れ、V8 の分類が不変。bootstrap 回数を増やして再確認する(追加の乱数のみで、予測実験ではない)。
- 不合格: V1〜V6、V8、V9 のどれかが外れる、または V8 の分類が 1 つでも変わる。

## 4. 成果物
- 別実装のコード(`backend/research/` 以外の、F1 の計算関数を import しない場所。例: `backend/research/p1_verification/`)、実行ログ、各検査の結果表(許容誤差と実測差)。
- 入力ファイルのハッシュ照合結果と、実行コミット。
- 結果は Study Manager に、F1 の監査補強の記録として別ノードで登録する。#889 と #937 の状態は変更しない。

## 5. 不一致が出た場合
- 不一致の内容(検査 ID、モデル、h、原点、差の大きさ)をそのまま記録する。
- F1 の結果を黙って書き換えない。原因が F1 側の実装なのか、再計算側の実装なのかを切り分け、結果は別の finding として報告する。
- F1 の判定に影響し得る場合は、ユーザーと監査担当者の判断を仰ぐ。

## 6. 範囲外
サンプラーの独立再実装、新しい期間やモデル(P4)、被覆率の原因診断(P2)、burn-in(P3)、F1 の再実行。

## 7. 承認が必要な事項
1. 独立性の定義と、再生成に本番コードを使う限界の受容。
2. V3 の抽出数(200 原点/セル)と、各許容誤差。
3. 不合格時の扱い(§5)。
