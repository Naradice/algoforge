## 2. 改訂①: 時刻の基準

### 2.1 根拠(結果を見た後の確認)

- HistData USDJPY は、週の開始が夏冬とも日曜 17 時台、月初の金曜の変動の最大が夏冬とも 08:30。
- 主データは、月曜 0 時台、15:30。月ごとの収益の相関は、46 か月で時差 +7 が最良。
- 2019-03 と 2020-03 は +8 が混じる。推定期間で、日曜 16 時台に始まる週が 6 週ある。

### 2.2 変換(事前に固定)

- **HistData**: 読み込み時に +7 時間する。ただし、暦の週(日曜〜土曜)の日曜の最初の足が 16:00〜16:29 の週は、その週全体を +8 時間する。判定に使うのは時刻だけ。
- **主データ**: 変換しない。
- 取引週の規則(時刻 + 6 時間の ISO 週)と窓の規則は、変換後の時刻に同じものを使う。HistData の日曜 17 時台が前の週に入る問題は、これで解消する。
- 季節性の刻みのニューヨーク時間は「変換後の時刻 − 7 時間」。感度の「固定 EST の刻み」は、ニューヨーク時間 → UTC → UTC−5 で作る。

### 2.3 確認と中止(R0。`volclust_50` は計算しない)

| 確認 | 対象 | 合格 |
|---|---|---|
| (a) 週の開始: 変換後の最初の足が月曜 00:00〜00:29 | 独立データ、他の 8 通貨(各期間)、主データ | 週の 95% 以上 |
| (b) 週ごとの 1 分収益の相関(一致する収益が 500 以上の週): 時差 0 が ±1 時間より高い | USDJPY、推定期間と検証期間 | 週の 98% 以上、かつ時差 0 の相関の中央値 0.9 以上 |

- USDJPY が (a) か (b) で不合格 → HistData を使う部分(独立データ、他の通貨)をすべて中止して報告する。
- 他の通貨が (a) で不合格 → その通貨は計算しない。
- 主データが (a) で不合格 → 主データの季節性調整値は計算しない。
- 不合格のとき、規則や基準値は直さない。
- 既に見えていること: (a) は、変換前の集計で、独立データが約 99%、主データの推定期間が 205/206 週。(b) と他の通貨は見ていない。

## 3. 改訂②: 出所の影響の基準

### 3.1 変える理由

主の判定が使うのは**窓の平均**なので、影響するのは出所による平均の偏り。元の基準(窓ごとの差の絶対値の平均)は、偏りがなくても、窓ごとのばらつきだけで超える。設計の誤り(私の設計)だが、**気づいたのは不合格を見た後**で、推定期間の平均差(−0.0010)も見ている。

### 3.2 新しい基準(R1)

- 量: 同じ時間の窓の `volclust_50` の差(HistData − 主データ)の平均。取引週のブロック再標本化(B = 2,000)の 90% 区間。
- 合格: **推定期間と検証期間の両方で、区間が ±0.0055(δ/4)に完全に収まる。**照合できる窓が、各期間の有効な窓の 80% 以上かつ 250 以上(照合の条件は元のまま: 時間内の HistData の収益 950 以上)。
- 不合格 → 独立データの判定は保留。**この基準は二度と作り直さず、研究を保留で終える。**
- 元の基準の値も、両期間で併記する(判定には使わない)。
- **推定期間は、合格することがほぼ分かっている。**事前の検査として意味があるのは、まだ見ていない検証期間の側だけで、偏りが同程度なら合格すると見込まれる。
- 限界: 2010〜2016 年の出所の差は、主データがないため確認できない。主の判定は HistData の中で閉じた比較で、この基準が守るのは「発見に使ったデータと同じ量を測っているか」である。
- 参考: 推定期間の偏りの符号は、HistData がわずかに低い(「差あり」には不利な向き)。

## 4. 判定規則は変えない(推奨)

### 4.1 理由

- V0 では、検証した帰無条件(真の差 = δ、DDM の真値の設定 2 通り)で、「差あり」の誤判定は観測されなかった(各設定 0/1,000、95% 区間 0〜0.4%)。真の誤判定率がゼロと示したものではなく、誤判定率だけから「差あり」と出た場合の信頼性は評価できない。
- ただし検出力は低い。真の差が δ + 0.01 でも「差あり」は 0/1,000 だった(これより大きい差は調べていない)。真の差が閾値を上回っていても、「差あり」と判定できない可能性が高い。
- したがって、この規則は誤判定を抑える一方、差の再現を確認できずに終わることが多くなりうる。
- 検出力を上げる変更は「差あり」を出やすくする向きで、推定期間の値(Δ ≈ 0.040、保留)を見た後に選ぶことになる。
- 規則を変えなければ、独立データを計算する前に、判定の閾値が実質的に決まっている(§4.2)。

### 4.2 実質的な閾値(保存済みの結果から。DDM 側は独立データに依存しない)

DDM 層の 90% 区間の下限は「実市場の平均 − 再標本の最大値の 95% 点」。この 95% 点は、V1 の全データで次の範囲にあった。

| DDM の組 | 再標本の最大値の 95% 点 | 「差あり」に必要な実市場の平均(δ = 0.022) |
|---|---|---|
| 136 点(SA / SB) | 0.029〜0.030 / 0.031〜0.032 | 約 0.054 以上 |
| 追加条件の 162 点(SA / SB) | 0.032 / 0.037〜0.038 | **約 0.060 以上** |

- **独立データの窓の平均が約 0.060 以上なら「差あり」、それ未満なら「判定保留」になる見込み**(実市場層の下限は、この水準では制約にならない)。再標本化の乱数で ±0.001 程度動く。
- 参考(既知の値): 推定期間の USDJPY は 0.053〜0.057 で保留、検証期間は 0.074 で「差あり」。独立データがどちらになるかは分からない。
- **「判定保留」は、差がないことを示さない。**平均が 0.054〜0.060 なら、追加条件だけが理由の保留になる。
- 一度計算すると、独立確認の余地はなくなる。保留でも、後から規則を変えて再判定することはしない。

### 4.3 変える場合の案(推奨しない)

点ごとの上側信頼限界の最大値を使う(交差・和検定)、SA と SB をまとめて 10 run にする、など。閾値は下がる見込みだが、下がる幅は計算していない。選ぶ場合は、本書を改訂し、新しい規則の V0(誤判定率と検出率)を合格基準つきで固定し直してから、承認を得る。DDM の run を増やす案は新しいシミュレーションで、本計画の対象外。
