## 0. 要約

1. **再生成は保存済みの累積収益とビット単位で全件一致した**。C3 の 4,000 経路(1,153 秒)と C0s の 4,000 経路(809 秒)で、不一致 0、失敗試行 0。ワーカー 1 と 18 の独立性の検査(各 32 回)も不一致 0。再生成の総数は 8,064 回(上限どおり)。
2. **A_config(アトラスの M1 統計量がアンサンブル設定でも成り立つか)は、候補の裾の重さに強く依存した**。
   - 尖度が約 3〜4.5 の軽い裾の候補(wma 15・40 など)は、アトラスの std とおおむね一致した(経路平均 std の対数比 −0.04〜+0.08)。
   - 尖度が 8 を超える重い裾の候補は、アトラスより経路平均の std が大きい(例: バケット 0 の (−0.3, 7) で +0.23 ± 0.10、バケット 15 の (−0.5, 7) で +0.30 ± 0.12、バケット 19 の重い裾の 7 候補で +0.12〜+0.73)。
   - バケットの混合の std レベルの比(アンサンブル/アトラス)は、バケット 0・8・15・19 で 1.03・1.01・1.07・1.51。**分散レベル**(プール分散)では `log(V_ens/σ²_atlas,mix)` が +0.257・+0.083・+0.449・+1.570 と、重い裾の経路に引かれて大きく開く。
3. **分解の再評価(D2)**: 測定した M1 分散を使うと、M1 項は代理量から +0.128(バケット 0)、+0.041(バケット 8)、+0.224(バケット 15)、+0.785(バケット 19)動き、**M3 項は同じ量だけ逆向きに動く**(和は不変)。測定後の M1' は 4 バケットとも正(+0.68、+0.23、+0.17、+0.78)、M3'(h1)は −0.43、−0.58、−0.84、−0.51 で、**バケット 19 の M3 項は正 → 負に反転する**(代理量では +0.28、測定では −0.51)。
4. **時間集約の直接測定(C2)**: DDM の M1 収益の窓内分散比 `VR_win(60)` は、バケット 0・8・15 の C3 で 0.146・0.149・0.152(バケット 19 は 0.360)。実現値は 0.80・0.84・0.78・0.81。1 次自己相関は DDM が −0.25〜−0.29、実現値が −0.01〜−0.04。DDM の窓内 VR は、ACF から導いた理論値と ±0.01 以内で一致した(窓内はほぼ定常)。**DDM は M1 レベルで強く平均回帰的で、60 本に集約すると分散が実現値の約 1/5 になる**。
5. **バケット 19 の反転**: 代理量による VR_C3 = 1.6〜2.0 は、**アトラスの std が重い裾の候補の M1 分散を過小評価していたことの影響**で、測定した M1 分散(プール)では経路間の VR_ens が 0.40〜0.46(< 1)になる。ACF は正に転じておらず、候補の ACF のラグ 1〜60 の和は −0.26〜−0.49。バケット 19 の VR が高いのは、軽い負の自己相関(acf_1 −0.15〜−0.27)の候補が多いため。**ただし、この M1 分散は重い裾の経路に支配される**。
6. **ショックの M1 レベルの影響は小さい**: C0s と C3 の M1 分散の比は 1.00・1.02・1.06・0.91。最初の 100 本の収益の std だけが 1.06〜1.08 倍で、以降は約 1.00 倍。M2(ショックあり・なしの観測差)の大半は、M1 レベルではなく**集約の寄与**(+0.14〜+0.64)。
7. **注意**: 経路間の分散は seed 間の差が大きい(C3 バケット 0 の h1 で seed 1 の標準偏差がプールの 1.23 倍)。V_ens は seed 1 の 1,000 経路だけの値で、重い裾の経路の影響を受ける。

## 1. 実行の記録

- **事前ゲート**(`results/pre_gates.json`)すべて PASS: 1a 生データのハッシュと、第 1 段階の保存値(バケット 0・8・15・19 の C0s・C3 の混合 std と 90% 幅)の 1e-12 での再現。1b `p3_sim.py`・`ddm_simulator.py`・`f1_ddm.py` が保存済みアンサンブルを作ったコミット(a113456、db0926f)と同一。1c 対象の 8 セルで `attempts = successes = 1000`(失敗試行 0)、試行 ID 0..999。4a 統計量の定義(アトラスの `full_characterize`、ACF のプロファイル(statsmodels と 1e-9)、`VR_win`(総当たりと 1e-12))。4b マッピングの使用窓 300 窓 × 4 バケットで `real_stats` を 1e-9、ACF プロファイルがマッピングの acf_1・5・20 と一致。
- **再生成ゲート**(`results/regen_C3.json`、`regen_C0s.json`): 成功経路 8,000 件の累積収益が保存値と `np.array_equal` で全件一致。並列独立性(各バケット・各条件 8 経路、計 64 回)も不一致 0。終値ファイルの SHA-256 のマニフェストは `regen_*.json` の `sha256`。
- **分析のゲート**: 5 分解の恒等性(M1' + M3' = M1 + M3、M2 の分割の和が M2)の最大残差 2.2×10⁻¹⁶。6 終値ファイルを再読み込みして SHA-256 が一致。
- **実装上の判断**:
  - M1 の窓は、最初の 1,000 本の収益(アトラス・マッピングと同じ)。同一時間範囲(最初の 60h 本)と全経路(1,440 本)の変種は JSON に保存した。
  - 「`V_ens,mix` は全経路のプール分散」。計画が求めた区別のため、**経路内分散の平均 `V_within` と、プール分散 `V_pooled`(経路間の平均の違いを含む)を別に報告**する。M1 レベルでは `V_pooled/V_within` が 1.000〜1.0004 で、経路ごとの平均収益の違いの寄与は無視できる。
  - D2 の分解は、計画どおり第 1 段階の標準偏差(3 seed、3,000 経路)を使うため、**M1' は seed 1 の V_ens、M3' の `VR_C3'` は「3 seed の sd ÷ seed 1 の V」という異なる標本の組み合わせ**になる。M1' と M3' の「代理量からの変化」(ΔM1 = ½ log(V_ens/σ²_atlas,mix))は標本に依存しないが、`VR_C3'` の絶対値は表 C2b(seed 1 の sd ÷ seed 1 の V)と違う(例: バケット 0 の h1 で 0.221 と 0.332)。
  - 窓内 VR(`VR_win`)と経路間 VR(`VR_ens`)は別の量として扱い、D2 には経路間 VR だけを使った。両者の一致は求めていない。

## 7. 解釈と限界

- A_config は、**差の大きさで読むべき**で、標準誤差の範囲に収まることだけで同等とは言えない。軽い裾の候補とバケット 0・8・15 の std レベルでは差が小さいが、重い裾の候補と分散レベルでは大きい。
- 分解の恒等性は数値実装の確認であり、各項が独立した因果寄与の証明ではない。M1 項と M3 項の内訳は、M1 分散の定義(分散かどうか、プールか経路内か)に依存し、重い裾の経路に左右される。
- 測定は 4 バケット・seed 1・2 条件に限る。1 候補あたり 125 経路で、候補別の統計量の誤差は大きい。バケット 17・18 は含まれない。
- V_ens は seed 1 の 1,000 経路のみ。経路間の標準偏差は seed 間で ±24%(バケット 0 の h1 で最大 1.23 倍)変わるため、分散比の絶対値は seed に敏感。D2 の `VR_C3'` は 3 seed の sd と seed 1 の V の組み合わせ(§1)。
- 再生成の一致は、同じコード・同じ乱数の下での決定性の確認であり、DDM の正しさの確認ではない。
- 実現値側の窓内 VR は、窓(1,000 本)内のみ。同一の期間・入力マッピングでの診断で、他の期間・市場への一般化は示さない。
