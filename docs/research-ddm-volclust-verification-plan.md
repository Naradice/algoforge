## 1. 目的と位置づけ

目的は、`volclust_50` を改善する仕組みを探すことではなく、**観測された差が再現性のあるものかを検証する**こと。順序を固定する。

1. 差の再現性・頑健性(推定の仕方、データ、別の説明)。
2. 到達可能な窓の偏りによる影響の切り分け。
3. **独立データの生の差と季節性調整後の差がともに「差あり」の場合に限り**、差を生む DDM 内部の機構の分析(コードと保存済みの系列)。
4. 追加機構・パラメータ探索は、別の計画と承認で判断する。

統計量が一致・不一致のどちらでも、DDM の市場生成機構が実市場を再現した、またはできないとは結論しない。

## 3. 前回の所見の弱点

1. **非対称な比較。** 事後分析の「窓の 62〜65% は `volclust_50` の範囲だけで届かない」は、1 つの実市場の窓を、DDM の**点平均**の範囲と比べている。保存済みの seed 間 SE からの粗い換算では、DDM の 1 窓のばらつきは約 0.029(A0: 5 seed 平均の SE の中央値 0.013 × √5)で、caliper 0.022 より大きい。「DDM がその窓の値を生成できない」とは読めない。
2. **先行結果の未引用。** 前回の計画 v0.6 は Phase 8b の結果ファイルを参考に挙げたが、報告と所見 #1122 は引用していない。
3. DDM の上限 0.015 は、136 個のノイズのある平均の最大値で、上に偏っている可能性がある(本計画では、この偏りを DDM 側に許容して比較する。§5)。

## 5. 主な量と判定規則(事前に固定)

- **推定量(変えない)**: 既存の `volclust_50`(対数収益の絶対値の ACF、ラグ 50)。窓は 1,000 本、重複なし、1 取引週内(前回の B の規則)。DDM は TPC=20。
- **実市場の量** `μ_real`: 窓の値の平均(感度: 中央値)。
- **DDM の量** `μ_max`: **全 10 seed が成功した 136 点すべて**の点平均の**最大値**。SA の組と SB の組で、別々に計算する(組ごとに 1 点 5 run)。点の選別はしない。
- **差**: `Δ = μ_real − μ_max`。
- **不確実性(合算しない 2 層)**、B = 2,000、90% 区間:
  - 実市場層: 取引週のブロック再標本化(`μ_max` は点推定に固定)。
  - DDM 層: 各点で run を再標本化し、**再標本ごとに 136 点の最大値を計算し直す**(`μ_real` は固定)。
  - DDM 層のパラメトリック t は参考として報告し、判定には使わない(136 点の最大値は、t 分布の裾に支配されるため)。
- **偏りの向き**: ノイズのある平均の最大値は、真の最大値より上に偏る。これは「差あり」には不利(保守的)だが、**「差は小さい」には有利**。後者の誤判定率は V0 で確認する。
- **比較の閾値 δ = 0.022**(感度: 0.010、0.030): 前回、DDM と比較する前に凍結した caliper(実市場の窓間 SD の 0.5 倍)を引き継ぐ。**窓単位の一致の許容幅と、平均差の重要性は同じ概念ではない。δ は比較のための運用上の閾値で、経済的・実質的な重要性は主張しない。**生の差がおよそ 0.035 になりそうなことは既に見えているため、生の差が閾値を超えること自体は独立な確認にならない。
- **3 区分の判定**。区間は「実市場層・DDM 層」×「SA・SB」の **4 つ**。
  - **差あり**: 4 つすべての下限 > δ
  - **差は小さい**: 4 つすべての上限 < δ(V0 で使えないと判定した場合は、この区分を使わない)
  - **判定保留**: それ以外
- **窓単位の補助量**(記述。判定に使わない): 同じ推定量の窓の値で、(a) 136 点すべての DDM 窓をまとめた分布、(b) 最大値となった点の DDM 窓の分布(同じデータで選ぶため上に偏る)と、実市場の窓の分布を比べる。実市場の窓が DDM の窓の 95% 点を超える割合と、`P(実市場の窓 > DDM の窓)` を、SA・SB の両方で報告する。

すべて**保存済みの DDM 価格系列と、手元の実市場データ**を使う。新しい DDM シミュレーションはしない。各段階のコードは、結果を見る前にコミットする。まとめて計算する版の `volclust_50` は、既存の関数と一致すること(差 1e-12 以下)を確認してから使う。

### V0 — 前提の点検と、判定規則の動作確認

実行の順序は 1 → 3。

1. **入力の確認(`volclust_50` は計算しない)**: `a1_stats.pkl` の SHA-256 と欠損の確認。主データ(`usdjpy_1min_volatility.parquet`)の出所と時刻の基準を、HistData の USDJPY と同じ時刻の行の照合で特定する。独立データの有効な窓と週の数を数える。時刻の基準を特定できない場合、R-A と検証期間の季節性調整値は計算しない。
2. **出所の影響**: 主データと HistData の同じ期間・同じ窓で `volclust_50` を比べる。差の絶対値の平均が δ/2 を超える場合は「出所の影響がある」と報告し、独立データの判定を止めて確認する。
3. **判定規則の動作確認**(前回、再現性の基準が seed のばらつきだけで約半分不合格になる設計だった)。
   - **点別の共通の真値**: SA と SB を区別せず、各点の 10 run から作る。2 通りの設定で行う。(a) 真値 `m_θ` = 点の 10 run の平均。(b) 全点が同じ真値(= (a) の最大値)。(b) は、最大値の偏りが最も大きくなる条件。
   - **擬似 DDM**: 真値から、**独立した 2 組(SA\*、SB\*)**を生成する。各点・各組 5 run = `m_θ` + その点の 10 run の偏差(中心化し √(10/9) 倍)からの復元抽出。
   - **擬似実市場**: R-A の窓の値を、平均が `max_θ m_θ + Δ_true` になるようにずらし、週を、独立データの有効な週数だけ復元抽出する。
   - **手順は本分析と同じ**(各組の 136 点の最大値、ブートストラップでの再計算、4 つの区間、3 区分)。擬似データ 1,000 組、内側の B = 500。
   - **報告**: `Δ_true = δ` のときに「差あり」と出る割合と「差は小さい」と出る割合を、設定 (a)・(b) の両方で、**実測値と二項分布の 95% 区間**(Clopper–Pearson)で示す。`Δ_true = δ + 0.01` と `δ − 0.01` の検出割合も示す(低くても規則は変えない)。
   - **基準**(1 区間の名目の片側誤り率は 5%。10% は緩めの上限): 実測の誤判定率が 10% 以下。
     - 「差あり」の誤判定率がどちらかの設定で 10% を超える → **停止して報告**(規則を直さない)。
     - 「差は小さい」の誤判定率がどちらかの設定で 10% を超える → **「差は小さい」の区分を使わず、判定保留にする**。
   - 限界: V0 は生の値で行い、季節性の再推定の影響は含まない。V1 の追加条件は区分を判定保留に変える方向にしか働かないため、V0 には含めない。

### V2 — 別の説明: 日中季節性

**主の調整は 1 つだけ。**

- **時刻の変換**: HistData の時刻は、夏時間を適用しない固定 EST(UTC−5。`docs/data-layer.md`)。**固定 UTC−5 として読み、UTC に直してから、`America/New_York` に変換する。**時刻の文字列をそのままニューヨーク時間とは解釈しない。窓と取引週の定義は前回のまま(固定 EST)で、季節性の刻みにだけニューヨーク時間を使う。
- **プロファイル**: ニューヨーク時間の 15 分刻み(曜日はまとめる)ごとの絶対収益の平均。同じ期間・同じ出所の、**対象の窓の週を除く週**から推定する。観測が 100 未満の刻みは、直前の刻みと併合する(先頭は直後)。窓の収益を、対応する刻みの値で割ってから `volclust_50` を計算する。
- **再標本化との整合**: **実市場層の再標本化のたびに、抽出した週からプロファイルを推定し直す**(対象の週は、重複して抽出された分もすべて除く)。そのプロファイルで窓の値を計算し直して `μ_real` を求める。固定したプロファイルは区間の計算に使わない。
- 調整後の差 `Δ_adj` に、§5 の判定(V1 の追加条件を含む)を適用する。**主の判定は独立データ(主)で行う**。R-A と検証期間の調整後の値は記述。
- **対照(注入、記述)**: DDM の窓に、実市場の窓の時刻に対応する季節性の規模を掛け、季節性だけでどれだけ `volclust_50` が生じるかを測る。
- 季節性で説明される割合 `1 − Δ_adj / Δ` と区間を報告する(記述)。
- 感度(記述): 固定 EST の刻み、曜日 × 30 分、窓内の絶対収益を 99% 点で打ち切り、ゼロ収益の割合が 0.10 以下の窓のみ、日ごとの水準で割る場合(クラスタリングの一部も除くため、分解の参考)。
- 一定ティック数の足による時計の違い(V2-T)は**含めない**。V2 の結果を見て、別計画として必要性を判断する。

### V3 — 到達可能な窓の偏り(記述・副次)

- 前回の主分割は `volclust_50` をマッチングに使ったため、到達可能な窓の `volclust_50` が DDM に近いのは選び方の帰結で、DDM の再現の証拠にならない。
- V3a(記述): 到達可能な窓と不能な窓を、`volclust_50`(生・調整後)、時刻、ATR 群、年、ジャンプの数、ゼロ収益の割合で比較する。
- V3b(条件付きの差): **評価する量をマッチングから外す**規則で、`M' = (acf_1, 尖度)`、`E = volclust_50`(生・調整後)。caliper、ノイズ床 `τ`・`f_0` は、前回と同じ手順で R-A・R-B から作り、**DDM との比較の前にコミットする**。判定は前回の `g = f − f_0`(閾値 0.05)を両層と、SA→SB・SB→SA の両方向で適用する。調整後の E では、再標本化のたびに季節性を推定し直す。
  - 到達可能な割合は、前回の「`volclust_50` の caliper を外す」で **20.2% と既に見えている**。M' は E を M から除く規則で決まるが、この値とは独立でない。
  - マッチング資格(主)と、資格を外した場合(感度)の両方を出す。方向で判定が違えば、条件付きの結果は結論に使わない。
  - 尖度の caliper が緩いため、分位点比に置き換えた感度分析を併記する。
- V3 は、V4 に進むかの判定には使わない。

### V4 — 機構の分析(独立データの生の差と調整後の差がともに「差あり」の場合のみ)

- **コードの読解**: 1 run の間に固定される量(各エージェントの `tend`、`dealer_sensitive`、WMA の重み、帰還なしのスプレッド)と、時間変化する量(注文価格、ポジション、価格履歴)を一覧にする。仮説の出発点: ゆっくり変わる状態がないため、絶対収益の相関が短いラグで消える。コード読解にもとづく仮説で、確認済みではない。
- **保存済みの系列**: 約定単位の価格から、絶対収益の ACF のラグ形状と、delta・wma との関係を記述する。
- 成果物: 機構の候補ごとの、反証できる予測と、それを調べる最小の実験の案。**実験は実行しない。**内部状態は保存していないため、観察には新しい run が必要で、別の承認とする。

## 9. 計算量と中止条件

- **V0〜V3 全体の上限は、最初の実行開始からの経過時間(壁時計)で 2 時間以内。**再実行、失敗した実行、段階間の待ち時間、中断した時間を、すべて含む。
  - 「最初の実行」は、研究データ(実市場データ、保存済みの DDM の結果)を読む最初のスクリプトの開始。コードは承認後、その前に実装してコミットする(合成した入力による動作確認は経過時間に含めない)。
  - 最初の実行で、共通の開始時刻と期限(開始 + 2 時間)を `results/deadline.json` に記録する。**上書き・削除しない。段階ごとにも再実行でもリセットしない。**
  - 各スクリプトはこの共通の値を参照し、期限を過ぎていれば開始しない。実行中も定期的に確認し、**期限を超えたら子プロセスを含めて停止して報告する**。残りの段階は実行せず、続けるには新しい承認を必要とする。
  - 台帳 `results/budget_ledger.json` には各スクリプトの開始・終了・実行時間を記録する(実行状況の把握用。上限の判定には使わない)。
- 2 時間で足りる見込みだが、測っていない(参考: 前回の A1 の窓統計は 318 秒)。独立データの CSV の読み込みを含む。途中で停止してレビューを待つ場合は、期限を超える可能性がある。
- V4 は、V4 の最初の実行開始からの経過時間で 1 時間以内とする(待ち時間などの扱いは同じ)。
- 中止して報告: V0 の「差あり」の誤判定率の不合格、出所の影響(独立データの判定を保留)、時間の期限。

## 11. 本計画で言えないこと

- DDM が原理的にクラスタリングを生成できない、ということ(探索したのは 300 体、delta × wma、ショックなしの格子)。

- δ を超える差の経済的な重要性。
