## 1. 要約

1. **独立データ(USDJPY 2010-01〜2016-08)の判定は保留。**V0 の出所の影響の基準(窓ごとの差の絶対値の平均 ≤ 0.011)を、0.0117 でわずかに超えた。計画どおり、**独立データの `volclust_50` は計算していない**。
2. **季節性調整(V2)は一つも計算していない。**独立データは保留、主データは時刻の基準を固定 EST と特定できなかったため。
3. **原因の確認で、前提の誤りが分かった。**手元の HistData の時刻は固定 EST ではなく、**ニューヨーク時間(夏時間あり)**だった。主データはその +7 時間。計画 V2 の時刻変換(固定 UTC−5 から変換)は、このデータには誤り。
4. **判定規則は、安全側に極端に偏っていた(V0)。**「差は小さい」の誤判定率は 99〜100% で、この区分は無効にした。「差あり」の誤判定率は 0% だが、真の差が δ + 0.01 でも検出率は 0% だった。
5. **記述の結果では、生の差はほぼすべてのデータで正。**実市場の平均は 0.045〜0.097、DDM の最大値は 0.011〜0.015(追加条件では最大 0.020)。ただし推定量の選び方に依存し、ラグ 100 と二乗収益では差が小さい。
6. **条件付きの差(V3b)は、`volclust_50` をマッチングから外しても、ノイズ床を超えた。**4 通り(両方向 × 資格の有無)で同じ判定。

## 2. V0: 前提の点検と判定規則

### 2.1 入力
- 保存済みの DDM 統計は SHA 一致、成功 run 1,593 の欠損なし。まとめて計算する版の `volclust_50` は、前回の窓の表と最大差 9×10⁻¹⁶。窓の作成も一致。
- 独立データ: 有効な窓 1,810(除外 92)、307 週。300 窓以上の条件は満たす。ゼロ収益の割合の中央値は 0.07。

### 2.2 時刻の基準と出所の影響

| 項目 | 結果 |
|---|---|
| 主データと HistData の 1 分収益の相関が最大になる時差 | **+7 時間**(夏 0.97、冬 0.96、全体 0.86。ほかの時差は 0.12 以下) |
| 固定 EST と特定する基準(時差 0 が最良) | **不合格** |
| 同じ窓の `volclust_50`(1,433 窓、時差 +7) | 差の絶対値の平均 **0.01168**(閾値 0.011)、中央値 0.0080、平均差 −0.0010、相関 0.93 |
| 扱い | **独立データの判定を保留** |

### 2.3 確認(結果を見た後に追加。判定は変えない)

| 確認 | HistData | 主データ |
|---|---|---|
| 週の最初の足(米国の夏 / 冬) | 日曜 17 時台 / 日曜 17 時台(推定期間 130/137 週・69/72 週。2010〜2016 年は 228/229・116/118) | 月曜 0 時台 / 月曜 0 時台 |
| 月初の金曜で変動が最大の分(夏 / 冬) | 08:30 / 08:30 | 15:30 / 15:30 |

- 固定 EST なら、夏は 1 時間早い時刻(16 時台、07:30)になる。**HistData はニューヨーク時間、主データはニューヨーク時間 + 7 時間**と整合的。
- 月ごとの最良の時差は 46 か月が +7、2019-03 と 2020-03 が +8、2016-08 は判定できない。
- 月ごとの最良の時差で照合し直しても、差の絶対値の平均は **0.01160** で閾値を超える。**保留の原因は時差の取り違えではない。**
- `docs/data-layer.md` の「HistData は固定 EST」と、これを引いた計画 §6 V2 は、手元のファイルには当てはまらない。調整の計算は実行していないため、誤った変換による結果はない。
- 取引週の規則(時刻 + 6 時間の ISO 週)は、主データでは正しく働く。HistData では日曜 17〜18 時が前の週に入り、その 1 時間は窓に使われない(§4 の他通貨の窓と、独立データの窓の数に影響)。
- **出所の影響の基準は、設計に弱点がある。**窓ごとの差の絶対値の平均は、窓ごとのばらつきを測る。主の判定が使う平均の偏り(−0.001)は測っていない。基準は私が決めたもので、結果を見た後には変えていない。

### 2.4 判定規則の動作(擬似データ 1,000 組)

| 真の差 | 設定 | 「差あり」 | 「差は小さい」(95% 区間) |
|---|---|---|---|
| δ(境界) | (a) 点ごとの 10 run 平均 | 0.0% [0.0, 0.4] | **99.4%** [98.7, 99.8] |
| δ(境界) | (b) 全点が同じ値 | 0.0% [0.0, 0.4] | **100%** [99.6, 100] |
| δ + 0.01 | (a) / (b) | 0.0% / 0.0% | 9.4% / 97.2% |
| δ − 0.01 | (a) / (b) | 0.0% / 0.0% | 100% / 100% |

- 「差あり」の誤判定は基準内のため続行した。**「差は小さい」は基準(10%)を超えたため、使わない。**
- 原因は、136 点の最大値の上方への偏りが、ブートストラップでさらに大きくなること。実データでも、再標本の最大値の中央値は観測した最大値より 0.0064〜0.0099 高い。
- したがって、本規則の「判定保留」は、差がないことを示さない。

- 計画 §7 の表の「独立データの生の差」が出ていないため、**どの行にも当たらない。再現性は確認できていない。V4 は実施しない。**

## 8. 実装上の具体化(実行前にコードで固定)

- 時刻の基準の特定: 時差 0 が全期間・夏・冬で最良、相関 0.5 以上、次点の 3 倍以上。特定できない場合の出所の照合は、最良の時差を使う。
- 出所の照合は、主データの窓の時間内に HistData の収益が 950 以上ある窓。照合できる窓が 300 未満なら保留。
- 季節性と V1 の再標本化の単位は取引週。HistData の重複した時刻は最初の行を残した(USDJPY で 120 行)。

## 9. 次に必要な判断

主の判定に進むには、**結果を見た後の変更**を含む計画の改訂と、新しい承認が必要。

1. 時刻の基準の訂正(HistData = ニューヨーク時間、主データ = +7 時間)と、取引週の規則の見直し。
2. 出所の影響の基準の作り直し(例: 平均の偏り)。保留を解く方向の変更になることを明示する。
3. 判定規則の見直し。現在の規則は、差が δ + 0.01 でも検出できない。

**独立データの `volclust_50` は計算していないため、改訂後の独立確認の余地は残っている**(窓の数、週の数、ゼロ収益の割合、週の開始時刻は見ている)。
