## 1. 問い
P2 で観測された特徴(final の h1・h4 の区間幅の不足 `k_90` 1.18/1.39 と上方向の中心のずれ、ATR 群・時間帯による不均一、推定期間でも不足、検証期間の h12・h24 は過剰被覆)のうち、**予測パスの開始直後の過渡状態(エージェント状態の未緩和と §11 の早期ショック)に由来する部分があるか**を、介入によって調べる。原因の確定や再較正は目的としない。

## 2. 監査で確認された事実(要約)
- DDM の予測は、原点の ATR バケットだけに依存する無条件のパス分布。実観測を状態に入力する仕組みはない(範囲外)。
- 各パスは、乱数から作った初期状態から始まる。§11 のショックは経過ステップ τ = 300(≈ 10 本のローソク足)で減衰し、期待ショック数は 1 パス 0.6 回(1 回以上起きる確率は約 45%)。ほとんどが最初の約 20 本に集中する。初期の過渡状態とショックは時間的に重なる。
- 乱数はすべて同じグローバルな `random` から引かれ、ショックが有効なときだけ毎ステップ消費されるため、ショックの有無を変えると最初のステップから乱数列が分岐する(監査文書 §7)。

## 3. 範囲と固定するもの
- 固定: マッピング(`ddm_mapping.json`)、バケットの定義、候補 (delta, wma) の集合、`N_AGENT`、ショックのパラメータ(P0 = 0.002、S = 0.3、τ = 300、床 0)、パス数 1,000/バケット、seed の規則、評価原点(P2 と同じ検証・final・推定の原点集合)、実現値 `y = log C1 − log C0`、ホライズン 1/4/12/24、入力ハッシュの照合。
- 範囲外: DDM の改修・再較正、実観測を状態に入力する方式、新しい期間・モデル(P4)、F1 の再評価。

## 4. 乱数の設計(共通乱数)
- 実装: `backend/research/p3_burnin/` に、`DDMv3` のサブクラス `DDMv3S` を置き、`_maybe_exogenous_shock` だけをオーバーライドする(シミュレータのソースは変更しない)。
  - **従来モード**(`shock_rng=None`): グローバルな `random` を使い、`DDMv3` と同じ処理。F1 の C0 のバイト単位の再現に使う。
  - **分離モード**(`shock_rng = random.Random(shock_seed)`): 毎ステップ、**ショックの確率が 0 でも、発生しなくても**、判定用と方向用の 2 つの乱数を `shock_rng` から必ず引く。発生判定は `u1 < p(t)`(p が 0 なら発生しない)、方向は `u2 < 0.5`。通常の状態更新の乱数列(時間ノイズなど)はグローバルな `random` に残る。
  - `shock_seed` は、パスの seed と決定的に結びつける(`shock_seed = seed + 500_000_000`)。
- 効果: 同じ seed の C0s、C1、C2、C3、C4、C5 で、初期状態、通常の状態更新の乱数列、ショック用の乱数列が共通になる。条件間の差は、ショックの閾値(発生するか否か)と窓の位置だけから生じる(強い対応比較)。
- **F1 の C0 とは別に C0s(分離モード、ショックあり、B = 0)を 3 seed 生成**し、P3 の主な対照とする。C0(F1)と C0s の差は乱数の結びつけ方の違いだけなので、**ノイズ範囲内(C0 の seed 間の差)に収まるかを報告**する(収まらない場合は、その旨を報告し、解釈で扱う)。

## 5. 条件(B ごと)
窓の定義: パスの先頭の `B + 1` 本のローソク足(`20·(B + 1)` 約定)を burn-in とし、その最後の終値を**窓の基準 `C_B`**とする。続く 1,440 本の終値を使い、予測値は `y_h^{(B)} = log C_{B+60h} − log C_B`(ホライズン h = 1, 4, 12, 24)。B = 0 は F1 の定義(`closes[60h]/closes[0]`)と一致する。

| 条件 | B | burn-in 中のショック | 予測期間のショック | 実装 |
|---|---|---|---|---|
| C0(F1) | 0 | あり | あり | F1 の保存済みアンサンブル(再現ゲートと整合性の確認用) |
| C0s | 0 | あり | あり(時計 0 から) | `DDMv3S` 分離モード(主な対照) |
| C3 | 0 | なし | なし | 確率 0(乱数は引く) |
| C1(B) | 15、60、240 | あり(時計は進む) | あり(減衰済みの時計のまま) | 長いパスを生成し、窓 `[B, B + 1440]` を使用 |
| C2(B) | 15、60、240 | あり | あり(**時計を 0 に戻す**) | B 本後に `_step_count = 0` を設定して続行 |
| C4(B) | 60(必須)、15・240(探索) | **なし** | なし | 確率 0 の長いパスの窓 |
| C5(B) | 15、60、240 | あり | **なし**(予測開始時に無効化) | B 本後に `exogenous_shock_probability = 0` を設定して続行 |

- 共通乱数のもとで、C0s と C1(B)、C2(B)、C5(B)は先頭 B + 1 本が同一。C3 と C4(B)も同一の通常の乱数列を共有し、C0s とは、ショックが発生した時点以降だけ状態が異なる。
- B の値(15、60、240)の根拠: ショックの τ ≈ 10 本。B = 15 で期待ショック数の残りが 0.14、60 で 0.002、240 で ~0。「緩和済み」と呼べるかは §8 の内部状態の診断で別に判断する(B の長さだけでは判定しない)。

## 6. 比較(介入ごとの差を個別に報告。2 × 2 の交互作用は主な比較にしない)
対応比較(同じ seed 番号)で、下記の差を個別に報告する。純粋な効果と呼べるのは、備考に明記した比較のみ。

| 比較 | 識別できること | 備考 |
|---|---|---|
| C3 対 C0s | ショックの存在(B = 0) | 純粋なショックの効果(共通乱数) |
| C1(B) 対 C0s | 窓を B 本後ろにずらした効果(緩和とショックの減衰の合成) | 純粋な緩和の効果とは呼ばない |
| C4(B) 対 C3 | **ショックがない場合の** burn-in 効果 | 純粋な緩和の効果に最も近い |
| C5(B) 対 C1(B) | 同じ burn-in 履歴の後に**残る減衰ショック**を除いた効果 | 同じ履歴 |
| C2(B) 対 C5(B) | 同じ burn-in 履歴の後に、時計を戻してショックを**再導入**した効果 | 同じ履歴 |
| C2(B) 対 C1(B) | 同じ burn-in 履歴の後に、時計をリセットする効果 | 同じ履歴 |
| C2(B) 対 C0s | 緩和後でもショックの時間構造は同じ場合の効果 | |
| C2(B) 対 C4(B)、C1(B) 対 C4(B) | burn-in 中のショック履歴と予測期間のショックを合わせた効果 | **burn-in 中の履歴も異なる**ので、純粋なショック再導入の効果とは呼ばない |
(要因計画の交互作用 (C2 − C1) − (C0s − C3) は、補足の記述としてのみ報告する。)

## 7. 実行の構成(必須セットと探索)
- 計算量: 1 seed(20 バケット × 1,000 パス)あたり約 1.5 時間(F1 の記録。B = 240 で +17%)。
- **フェーズ 0(ゲート。本実験の前に、結果を報告して停止しない構成: 全ゲートが通れば続行、1 つでも失敗すれば停止して報告)**: §9 のゲートと、§8 の内部状態の診断。
- **フェーズ 1(必須セット。段階 1 の結果によらず、3 seed(seed_id 1、2、3)で実行)**: **C0s、C3、C1(60)、C2(60)、C5(60)、C4(60)**(合計 6 条件 × 3 seed = 18 回、約 30 時間)。主な報告。
- **フェーズ 2(探索的。選択バイアスがあるため探索的結果として報告)**: B = 15 と 240 の C1、C2、C5(計 6 条件)を seed 1 で実行(約 10 時間)。その結果が次の「注目基準」のいずれかを満たす条件は、seed 2・3 も実行する。基準(計算資源の配分基準であり、科学的な合否基準ではない): いずれかの期間・h のセルで、対応する C0s(seed 1)と比べて、90% 被覆率の変化 ≥ 2 パーセントポイント、CRPS の相対変化 ≥ 0.5%、`k_90` の変化 ≥ 0.10、`P(y>m)` の変化 ≥ 0.03、のいずれか。C4(15)、C4(240) は、フェーズ 1 の結果を見て必要なら追加(探索的)。
- フェーズ 2 の結果は、「注目基準を満たした条件のみ追加の seed を実行した」ことを明記して報告し、**基準を満たさなかったことから「効果なし」とは結論しない**(「この条件・この指標・この B で、ノイズ範囲を超える変化は観測されなかった」とのみ記述する)。

## 8. 内部状態の緩和の診断(実現値を使わない。「緩和済み」と呼べるかの確認)
- 目的: B の長さだけでなく、実際の内部状態が緩和したかを確認する(較正の改善を判定するものではない)。
- 設計: 各バケット 50 パス(診断用の seed_id = 9。アンサンブルの seed とは別)を、C3(ショックなし)と C0s(ショックあり)の 2 設定で、1,440 + 1 本まで生成し、ローソク足の番号 {0, 1, 2, 5, 10, 15, 30, 60, 120, 240, 480, 960, 1440} の時点で、次の状態量を記録する: ポジションの偏り `|買い − 売り| / N`、エージェント価格の標準偏差、買い気配と売り気配の差(`max(買いの価格) − (min(売りの価格) + spread)`)、WMA 追従項の大きさ、直近のローソク足の平均絶対リターン(窓 5 本)、現在のショック確率。
- **「緩和済み(この指標で)」の基準(事前固定)**: 各状態量で、時点 t の平均が、後期の基準(時点 960 と 1440 の平均)から相対 5% 以内。B = 15、60、240 のそれぞれで、全状態量が基準を満たせば「緩和済み(この指標で)」、満たさなければ、報告では「B 本経過後(緩和は未確認)」と呼び、「緩和済み」とは書かない。
- 結果は、全バケットの平均とバケット別の両方を保存する。

## 9. 実装前のゲート(どれかが失敗すれば実行しない。P3 のコードを `backend/research/p3_burnin/` にコミットしてから実行する)
1. **C0 のバイト単位の再現**: `DDMv3S` の従来モード(または `DDMv3` そのもの)で、同じ seed・同じコードにより、バケット 0、10、19(seed 1)を再生成し、保存済みの `ddm_ens_seed1.npy` と配列が一致すること。不一致なら環境差を調査して停止。
2. **窓の厳密な単体テスト**: (a) B = 0 の窓と予測値が `f1_ddm.simulate_long_path`・`cum_returns` と一致。(b) 任意の B で、窓の長さが 1,441 で、窓の基準 `C_B` が `20·(B + 1)` 番目の約定価格で、`y_h^{(B)} = log C_{B+60h} − log C_B`(h = 1, 4, 12, 24)であること(手計算の小さな例を含む)。(c) C1(B) の最初の `B + 1` 本が、同じ seed の C0s の先頭と一致すること。C2、C5 でも同様。
3. **介入の単体テスト**: (a) C2 で、記録開始直前に `_step_count == 0` で、直後のショック確率が P0。(b) C5 で、記録開始後のショック確率が 0 で、ショックのイベントが 0。(c) C3、C4 で、ショックのイベントが 0。(d) 分離モードで、ショックの有無にかかわらず `shock_rng` の消費数が同一(毎ステップ 2 個)で、通常の乱数列(`random` の状態)が、C0s、C3、C1、C2、C4、C5 で同一ステップ数まで一致すること(ショックが発生していない区間)。(e) `DDMv3S` の従来モードと `DDMv3` の出力がバイト単位で一致。
4. **パス単位の対応関係**: 条件ごとに、採用された attempt ID(バケット × パス位置)を保存する。失敗パス(`None`)の割合を条件別に記録。同じ attempt ID に対応するパスだけを、パス単位の対応比較として扱う(対応率を報告)。アンサンブル単位の比較(原点ごとの CRPS など)は全パスで行う。
5. **未来情報の混入がないこと**(必須): 新規アンサンブルの生成コードが、マッピング(推定期間のみ)以外の実データを読まないこと。バケットの割り当て(原点の ATR)が P2 と同一であること(原点ごとのバケット配列のハッシュ照合)。
6. 入力ハッシュ(58 ファイルと生データ)の照合、実行コミットの記録、出力は新しい作業ディレクトリ(既存成果物は変更しない)。

## 10. 主要な評価量と比較の方法
比較はすべて、**同じ評価原点、同じ実現値、同じホライズン、同じアンサンブル数(M = 1000/seed)**で、同じ seed 番号の条件の間で行う。原点集合は P2 と同一で、変わらない。

優先順位(事前固定):
1. **CRPS(予測性能)**: 原点ごとの fair CRPS の、対照との差(相対変化)。F1 で選ばれた統計モデルの CRPS との比(F1 の Δ_h と同じ定義)も記述として併記するが、新たな分類はしない。
2. **較正**: 90%・50% の被覆率、`k_90`、`k_50`(P2 と同じ定義)。
3. **中心と形状**: `P(y > m)`、PIT の平均・分散、75%・25% 分位点の超過率の差。
4. **一貫性**: ATR 群別(5 群)、期間別(検証 / final / 推定)、ホライズン別。

不確かさの評価:
- **ノイズの基準**: C0 の seed 間の差(F1 の seed 1〜3 の保存済みアンサンブルから、各セル・各指標で最大 − 最小)。フェーズ 1 では、C0s の seed 間の差も併せて使う。条件の効果は、この範囲との比較を主とする。
- 週ブロック bootstrap(10,000 回)の対応差の 95% 区間は、**記述的な目安**として併記する。P2 で、アンサンブルの標本誤差の共有により検定が名目より過剰に棄却されることを確認しているため、**p 値と有意性による判断は行わない**。
- 「注目基準」(被覆率 2pp、CRPS 0.5%、`k_90` 0.10、`P(y>m)` 0.03)は報告の目安であり、合否の閾値ではない。

## 11. 解釈の規則(事前固定。因果は断定しない)
- 各比較(§6)の効果が、ノイズの範囲(C0 の seed 間の差、C0s の seed 間の差)に収まる: この B の範囲・この指標では、ノイズ範囲を超える変化は観測されなかった(「効果なし」とは書かない)。
- C3 対 C0s が変化: ショックの存在が寄与する可能性。C4(B) 対 C3 が変化: ショックがない場合の過渡状態の寄与の可能性。C5(B) 対 C1(B)、C2(B) 対 C5(B) が変化: 同じ burn-in 履歴の後のショックの扱いが寄与する可能性。
- 較正が名目に近づき、CRPS も改善(ノイズ範囲を超える): 分布として改善と整合する。被覆率のみ改善して CRPS が改善しない(または悪化): 幅の拡大のみと整合し、予測性能の改善の証拠にはならない。
- 「緩和済み」の語は、§8 の基準を満たした B にのみ使う。
- P2 の特徴ごとの対応: h1・h4 の幅の不足 → `k_90`、被覆率、CRPS。中心のずれ → `P(y>m)`、75% 分位点。ATR 依存 → ATR 群別の被覆率と `k_90`。推定期間の不足 → 推定期間の被覆率。h12・h24 の期間差 → 検証と final の被覆率の差の変化。

## 13. 限界
- 実観測を状態に入力する方式は検証しない。DDM は履歴を条件としない無条件のパス分布であり、burn-in はシミュレーション内の過渡状態の影響を見る介入にとどまる。
- P2 の限界を引き継ぐ: 探索的、final 期間は部分的に既知、p 値は名目の保証なし、週ブロック bootstrap はアンサンブルの標本誤差の共有と週をまたぐ依存を捕捉しない。
- 1 候補・12 パスの監査計測は一般化できない。エージェント状態の緩和は §8 の診断で確認するが、診断も限られたパス数・状態量に基づく。
- 共通乱数の設計は、F1 の C0 とは乱数の結びつけ方が異なる(C0s)。C0 と C0s の差がノイズ範囲に収まらない場合は、解釈で扱う。
- ATR・時間帯・期間は交絡しており、条件の効果の局面別の解釈に因果は主張しない。
- フェーズ 2 は探索的(選択バイアスあり)。
