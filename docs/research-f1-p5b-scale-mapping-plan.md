## 1. コードと記録から確認した事実(分析前)

1. **マッピング**(`f1_ddm.py`、`ddm_ensemble_selection.py`): 各バケットで、推定期間の原点から最大 300 件(`used_blocks`)の実現値の**前向き M1 窓**(原点から 1,001 本の終値、1,000 本の対数収益)の統計量(std、歪度、尖度、acf_1・5・20、volclust_50)を平均し、アトラスから候補を選ぶ。選択は**まず std の近さで 30 点に絞り**(`|log std_atlas − log std_real|`)、その中で acf_1 と volclust_50 の近さ(重み 0.25 ずつ)で順位づけし、上位 8 点(delta, wma)を候補とする。`best_std_ratio` は **max(std_sim/std_real, std_real/std_sim)**(符号を持たない)。`out_of_range`(比 > 2.0)は全バケットで False。
2. **アトラス**(`ddm_regime_atlas.csv`、`calibrate_ddm.py`): 176 点(delta 16 × wma 11)、各点 5 seed、各 seed 20,000 取引(= 1,000 足、1 足 = 20 取引)、**300 エージェント、§11 の外生ショックなし**(`exogenous_shock_probability` の既定値 0)。統計量は 1,000 足の終値収益から計算。
3. **アンサンブル**(`f1_ddm.py`): 同じ 300 エージェントに**§11 の減衰ショック**(確率 0.002、サイズ 0.3、減衰 300 ステップ)を加え、1,441 足(= `60 × 24 + 1`)の経路を生成。h = 1/4/12/24 の累積対数収益(60h 足後)だけを保存。**M1(1 足)レベルの経路は保存されていない**。
4. **P3 の結果**: ショックなし(C3)では、DDM の幅が大きく狭まる(被覆率 final 0.63〜0.76)。ショックの絶対サイズは ATR バケットによらず一定なので、**低 ATR ほど相対的な寄与が大きいはず**(仮説 M2。まだ確認していない)。
5. **P5-A の結果**: バケット 0〜16 で DDM/E1a の尺度比は ATR とともに系統的に低下。`best_std_ratio` との順位相関は +0.82(符号なしの比のため解釈に注意)。`best_std_ratio` が約 1.0〜1.1 のバケット 12〜16 でも DDM の 60 分足の幅は E1a の 0.5〜0.7 倍。DDM の幅の増え方(傾き)が実現値と違う(h1→h4 で遅く、h4 以降で速い)。
6. **保存済みの C0s・C3 の `.npz` には各経路の試行 ID** があり、`attempt % 8` で候補を復元できる(P5-A のゲートで検証済み)。

## 3. 分析計画 — 第 1 段階(保存済みデータのみ。DDM の新規生成なし)

### A. マッピングの M1 レベルの検査(M1・M5)

- バケットごとに、実現値の M1 統計量(`ddm_mapping.json` の `real_stats` を、`used_blocks` の窓から**生データで再計算して一致を確認**したうえで使う)と、8 候補のアトラスの統計量(std、acf_1、acf_5、acf_20、尖度、volclust_50)を並べる。
- `log(std_atlas / std_real)` を**符号つきで**候補ごとに示す(`best_std_ratio` は符号を持たないため)。この表の `std_real` は**マッピングが使った値(`real_std`、窓ごとの標準偏差の平均)**で、元のマッピングの再現を目的とする。
- **分散の定義の統一**(分解用): 実現値側は各窓の**分散**の平均 `V_real,M1`(§3B)、アトラス側は候補 c の `σ²_atlas,c = std_c² + (std_std_across_seeds)_c²`(seed ごとの標準偏差の平均と seed 間の標準偏差から、seed ごとの分散の平均を復元する。`np.nanstd` は ddof=0)。マッピングの `real_std` と `√V_real,M1` の差(比)は、バケットごとに別に記録する。
- **混合の定義**: アトラスには**候補別の平均収益が保存されていない**ため、候補間の平均の違いによる分散 `Σ w_c (μ_c − μ_mix)²` は含められない。そのため、**混合の M1 分散は候補内分散に基づく代理量** `σ²_atlas,mix = (1/8) Σ_c σ²_atlas,c`(等重み)と明記する。この代理量に基づく §3D の分解は、真の M1 混合分散を識別したものとは扱わない。参考として、C0s・C3 のアンサンブルから、候補別の 60h 足の収益の平均と標準偏差の比 `|μ_c|/sd_c`(および候補間の平均のばらつき)を示し、候補間の平均の違いが小さいかを間接的に確認する(間接的な指標であり、M1 レベルでの確認ではない)。
- アトラスの std の範囲(最小・最大)、実現値の std の ±10%・±25% 以内にあるアトラス点の数(バケット別)、30 点の短絡(shortlist)が acf_1・volclust_50 の順位づけで実際にどれだけ std の許容幅を使ったか(shortlist 内の std の範囲)。
- M5: バケット別の、現在の ATR の代表値(バケットの中央値)と、前向き M1 std の平均、E1a の 60 分足の std の関係(記述のみ)。

### B. 実現値側の時間集約(M3)

- 推定期間の原点について、生データから、バケット別・ホライズン別の **分散比** `VR_real(h) = Var(y_h) / (60h × V_real,M1)` を計算する。**`V_real,M1` は、各原点の前向き 1,000 本の M1 収益の分散(各窓の分散。マッピングの `compute_return_dist` と同じ ddof)の平均**で、§3A・§3D でも同じ量を使う。マッピングの `real_std`(窓ごとの標準偏差の平均)とは別の量なので、`√V_real,M1 / real_std` をバケットごとに記録する。`y_h` は P4・P5-A と同じ(`log C[t+60h] − log C[t]`)。
- **h12・h24 の位置づけ**: 前向き窓(1,000 本)は 60h 足(h12 で 720 本、h24 で 1,440 本)と範囲が異なる。h24 は 1,000 本の窓の分散で 1,440 本先の分散を規格化するため、**同一時間範囲の分散比ではなく、前向き 1,000 本を基準とした規格化指標**である。h1・h4 を主、h12 以降は補助の診断とし、h24 の値を分散比の物理的な意味で解釈しない。
- 不確かさ: 週ブロック bootstrap(B = 2,000、記述的)。
- 検証・final について、ATR 群別の `VR_real` を**期間外の文脈**として併記する(群別のバケット・マッピングは推定期間のものを使う)。

### C. DDM 側の時間集約(M2・M3)

- C0s と C3 のアンサンブルの保存値から、バケット別・候補別・ホライズン別の 60h 足の累積収益の分散を計算する(C0s: ショックあり、C3: ショックなし)。
- **ショックあり・なしの保存済みアンサンブル間の観測差(M2、アトラスの仮定を使わない)**: バケット別・ホライズン別の `width90(C0s) / width90(C3)` と `std(C0s) / std(C3)`。ATR との関係(順位相関は記述のみ)と、E1a に対する `C0s/E1a`・`C3/E1a`。**これは「ショックあり・なしの保存済みアンサンブル間の観測差」であり、ショックの純粋な因果効果ではない**: P3 の C0s と C3 は共通の乱数系列(ショック用に別の乱数生成器を使う設計)で作られているが、最初のショック以後は状態の推移が異なり、ショックと他の内部状態の変化の寄与は分離できない。**直接観測できるもの**: 標準偏差比・90% 幅比とその ATR 依存、分布の差。**直接確定できないもの**: 同一経路にショックを加えた場合の純粋な効果、ショックが低 ATR で相対的に強く作用する機構、ショックと他の内部状態変化の寄与の分離。M2 との整合性は評価できるが、因果効果の確定ではない。
- **暗黙の分散比(M3、仮定つき)**: C3 の候補ごとに `VR_DDM(c, h) = Var_C3(c, h) / (60h × σ²_atlas(c))`。**仮定 A_config**: 「アトラスの std は、C3 の M1 std の代理として使える」(同じ 300 エージェント・ショックなしだが、1,000 足 vs 1,441 足、初期の過渡の扱いが違う)。この仮定は第 1 段階では検証できない(§5)。

### D. 対数幅の比の分解

バケット × ホライズンで、std ベースの DDM と実現値の比(P5-A の 90% 幅の比に対応する std 版)を次の恒等式で分解する(**定義上、代数的に成立する。仮定 A_config のもとで**。M1 項と M3 項は、アトラスの std を M1 std の代理として使う限り、この仮定に依存する):

```
log( sd_C0s / sd_E1a ) =  log( σ_atlas,mix / √V_real,M1 )         … M1 レベルのずれ(M1)
                        + ½ log( VR_C3 / VR_real )               … 時間集約のずれ(M3)
                        + log( sd_C0s / sd_C3 )                  … ショックあり・なしの観測差(M2 と整合的かを見る)
```

定義: `sd_C3² = VR_C3 × 60h × σ²_atlas,mix`、`sd_E1a² = VR_real × 60h × V_real,M1`。`σ²_atlas,mix` は §3A の**候補内分散に基づく代理量**(候補間の平均の違いを含まない)、`V_real,M1` は §3B の**窓ごとの分散の平均**。第 3 項は「ショックあり・なしの保存済みアンサンブル間の差」であり、純粋なショック効果ではない。各項のバケット依存(傾き、順位相関)を記述し、**どの項が P5-A の尺度比のバケット依存を主に説明するか**を示す。**分解が恒等式として成立することと、M1・M2・M3 の物理的な寄与が識別できることは別**であり、M1 項と M3 項は A_config に依存する。分解は **90% 幅についても同様の表**(第 3 項は幅の比、他の項は std の恒等式の残差として)を併記する(尾が重いため std と幅は一致しない)。

### E. 候補集合の被覆(M4)

C0s・C3 それぞれで、バケット別・ホライズン別に、8 候補の 60h 足の幅の最小・最大と E1a の幅の関係(P5-A の D1 の拡張)。M1・M2・M3 の分解の結果と対応づけて、「候補集合が必要な尺度を含まない」のが M1(アトラスの被覆)、M2(ショック)、M3(時間集約)のどれに由来するかを記述する。

## 4. 第 2 段階(任意。**新規のシミュレーションを含むため、別途承認が必要。この計画の承認範囲に含めない**)

第 1 段階では、**ensemble 設定での DDM の M1 レベルの統計量**(仮定 A_config の検証)を直接見られない。必要になった場合に限り、次を別計画として提案する。

- **必要性**: 第 1 段階の分解が仮定 A_config に強く依存し、M1 と M3 の寄与が識別できない場合。
- **内容**: 保存済みの経路を**同じ試行 ID・同じ seed で再生成**し(アンサンブルの累積収益と**ビット単位で一致することを確認**)、同時に M1 レベルの経路(1 足ごとの終値)から、1 足の std、acf、分散比 `VR(k)`(k = 5、20、60、240、720、1440)を保存する。対象は少数のバケット(例: 0、8、15)× 8 候補 × 各 100 経路程度(C0s と C3)。
- **計算量の目安**: F1 の生成は 1,000 経路 × 20 バケット(約 20,000 経路)が 80〜90 分(18 ワーカー)。上の規模(約 4,800 経路)は 20〜30 分程度の見込み。

## 5. 事前ゲート(失敗したら停止して報告)

1. **入力の同一性**: 生データのハッシュ、P5-A の保存値(DDM/E1a の分位点の比、候補の 90% 幅)の再現。
2. **マッピングの再現**: `used_blocks` の窓から再計算した M1 統計量(窓ごとの標準偏差の平均)が、`real_stats` と一致(浮動小数点の許容 1e-9)。窓が推定期間内で終わる(ギャップなし)ことを確認。あわせて、窓ごとの分散の平均 `V_real,M1` を計算し、`√V_real,M1 / real_std` を記録する(この比は一致を要求せず、差の記録のみ)。
3. **アトラスの照合**: 8 候補 × 20 バケットの (delta, wma) がアトラスに一意に存在し、統計量が有限。
4. **候補の復元**: C0s・C3 の試行 ID から復元した候補が、P5-A と同じ規則で一致(ゲートの再利用)。
5. **分解の恒等性**: §3D の分解の和が全体の対数比と一致(1e-12)。使用する量(`V_real,M1`、`σ²_atlas,mix`、`VR_C3`、`VR_real`)が §3A・§3B の定義と同一であることも確認する。
6. **将来情報なし**: 実現値側の VR は推定期間の原点だけで計算し、窓がその期間の外に出ない。

## 6. 報告の規則

**結果の判断の順序**(仮定に依存しない知見を先に取り出す):
1. ショックあり・なしの保存済みアンサンブルの差(C0s と C3)が、P5-A で見つかった ATR 依存の尺度不一致をどれだけ説明するか(A_config に依存しない)。
2. ショックなしの C3 でも、同様の ATR 依存が残るか(C3/E1a のバケット別の比)。
3. 残った差が、アトラスの M1 統計量(M1 項)と時間集約(M3 項)のどちらに整合的か(A_config に依存。その旨を明記)。
4. A_config の不確かさが大きく、両者を識別できない場合にのみ、第 2 段階を別計画として検討する。

- バケット別(推定期間)と、ATR 群別・期間別(検証・final は文脈)の表を主とし、各セルの n、週数を示す。未定義の比(分母 0 など)は 0 や 1 に置き換えず、件数を報告する。
- p 値で判断しない。効果量と記述的な区間(週ブロック bootstrap)を示す。アトラスの std の不確かさとして `std_std_across_seeds`(5 seed)を併記する。
- 「整合的」と原因の確定を区別する。分解は代数的な恒等式であり、因果の識別ではない。A_config の仮定を結果の各表に明記する。
- 保存済みデータだけで識別できないもの(ensemble 設定の M1 統計量、1,001 足と 1,441 足の違い、初期の過渡)を明示する。
- final の結果で、定義や基準を変更しない。F1 の判定期間は部分的に既知。

## 10. 限界

- 仮定 A_config(アトラスの std は ensemble 設定の M1 std の代理)は第 1 段階では検証できない。分解の M1 項と M3 項は、この仮定に依存する。M2(ショック)の項は C0s と C3 の保存値だけで求まり、仮定に依存しない。
- アトラスは 176 点・5 seed で、std にはサンプリング誤差がある(`std_std_across_seeds`)。
- 候補は 8 点の等重み混合で、アトラスに候補別の平均がないため、M1 の混合分散は候補内分散に基づく代理量(候補間の平均の違いを含まない)。アンサンブル側(C0s・C3)の分散には、候補間の平均の違いが含まれる。
- 実現値の分散比には、期間・市場環境の違いが混ざる。検証・final は文脈であり、推定期間の結論を確定させるものではない。
- 同一の期間・入力マッピングでの診断で、他の期間・市場への一般化は示さない。
