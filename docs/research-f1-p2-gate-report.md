## 実装不具合かどうかの切り分け(計画 §6 の規則 (a)/(b))
コードも基準も変えずに、ケース 1 の予測標本だけを変えた診断(`p2_synth_diag.py`、各 1,000 試行、棄却率):

| 変種 | FA90 | FB | FC | FE |
|---|---|---|---|---|
| V0 計画どおり(M=1000 の乱数アンサンブル、バケットごとに約 150 原点が共有) | 0.088 | 0.067 | 0.081 | 0.081 |
| V1 標本誤差なし(予測分位点の格子、M=1000) | 0.054 | 0.049 | 0.064 | 0.072 |
| V2 M=20,000 の乱数アンサンブル | 0.055 | 0.044 | 0.061 | 0.071 |

解釈: 過剰な棄却は、有限のアンサンブル(M=1000)の標本誤差が、同じバケットの原点間で共有され、週ブロック bootstrap では捕捉されないことによる。実装の誤りではなく、検定の設計(と実データの構造)の性質と判断する。仕様どおりの実装で、基準に届かなかった。V1/V2 でも FC・FE は 5% をやや上回る(B=1000 の bootstrap と推定の有限性による)。

## 計画 §6 (b) に従った扱い
検定方法・統計量・基準・seed は変更しない。実データの診断(D1〜D8)に進まず、計画の再審査に回す。実データの検定でも、同じ原因(DDM のバケット別アンサンブルの標本誤差が週ブロック bootstrap で捕捉されない)により、第一種の誤りが名目より大きくなり得る。この点の扱い(例: 検定の解釈の注意の追加、アンサンブルの標本誤差を bootstrap に含める設計、M の影響を確認する感度分析)は、再審査での判断事項。
