## 改訂後の本文(全文)

### 目的

確率予測に基づく市場異常検知について、異常の種類ごとに適切な時間スケールと検出要件を整理し、後続の A1 で検証する対象を選ぶ。A0 は操作的定義・データ要件・評価設計を確定する段階で、**どの期間でも検知スコアを計算せず、検知性能を比較しない。**

### 研究上の前提

- **F1(#889、2026-11-18 実行・事後監査済み)。** この評価条件では、h=1・4 は統計モデルが良い、h=12 は判定保留、h=24 は同等。ホライズン横断の判定規則が事前登録されていないため、全体は inconclusive。
- **F1 の予測の単位。** M1 60 本を 1 窓とした累積対数収益の 1・4・12・24 窓先(60〜1,440 本)で、原点は 60 本ごと。**M1 1 本先や毎分更新の予測分布はない。**
- **F1 の追加分析(P2〜P5、探索的・記述的で inconclusive)。** ATR・時間帯・期間・ホライズンによる校正状態の差が記述的に観測された。原因は未確定。P4 では、最終期間の h=1・4 で、ATR バケット別の経験分布が DDM より校正され、CRPS も約 2.2〜2.5% 小さかった。
- **Atlas。** 既存の 170 点には、20 の ATR バケットのいずれでも、標準偏差とラグ 1 自己相関の許容帯を同時に満たす点がない。原因は未確定。
- **T(#895、#1135)。** 同じイベント列で時計だけを変えると固定時間の活動統計は変わり、20 約定を 1 本とする足は 20/20 本の系列で一致した(時計が価格生成に入らないため)。約定数基準と固定時間基準を混同しない。固定時間で DDM を使う場合は時計を明示し(T1 の規約は 1 約定 3 秒、毎分 20 約定)、リポジトリの時計(1 分あたり約 2,450 約定)はそのまま使わない。T1 は v3_shock・500 体の結果で、他の設定への外挿は未確認。
- **PIT(#938)。** 実現値は `y = log C1 − log C0` に固定する。乱択 PIT は同値の判定で不連続になり、等価な別の式で結果が変わりうる。
- **将来の急変動の既存結果(Phase 10A、`docs/research-periodic-forcing-transfer.md`)。** 20 本先の極端な変動(|r| が 99.9% 点超)は、過去の収益と時刻から、線形で AUC 0.856、勾配ブースティングで 0.876(データセット 29。149 では 0.849 → 0.861)。異常検知の評価ではないが、事前予測には強い単純な比較相手がある。
- **時刻の基準。** `usdjpy_1min_volatility.parquet` の時刻はニューヨーク時間 + 7 時間(推定・検証期間で確認。2021-09 以降は未確認)。P2・P4 の「UTC 00–08」などの区分はこのファイルの時刻で、UTC ではない。HistData の CSV はニューヨークの現地時間(USDJPY で確認)。
- 以上は設計上の制約で、特定の時間スケールで異常検知が有効であることの証拠ではない。F1 の追加の原因分析は A0 の前提条件にしない。

### 1. 異常の分類と操作的定義

次の対象を区別する。

1. **観測異常:** 通常の変動に対して極端な価格変化・活動量などが観測されること。
2. **予測分布の不適合:** 予測分布と実現値の不一致(PIT、被覆率、裾確率などで評価)。
3. **市場状態の変化:** ボラティリティ、相関、自己相関、活動統計などの持続的な変化。
4. **将来危険状態:** 定義済みの将来期間内の急変動・流動性低下などを事前に予測する課題。

各対象で、開始・終了、強度、持続時間、イベントをまとめる最小間隔、ラベルの生成方法、閾値の推定期間を定義する。

**ラベルは、比較するスコアとの独立性で分ける。**

| 区分 | 定義 | 扱い |
|---|---|---|
| L1 外部情報 | スコアが使う価格・活動の系列とは別の情報源(例: 経済指標の発表、公表された介入) | 性能を比較できる。入手可否と時刻の精度を A0-3 で確認する。予定された出来事は市場異常の正解とは限らない |
| L2 将来区間 | 時点 t のスコアが使えない、t より後の区間から作る(例: (t, t+H] の実現変動幅) | 性能を比較できる(事前予測)。同じ系列なので、変動の持続性を使うスコアが有利になりうる |
| L3 同じ区間 | スコアと同じ区間・同じ情報から作る | **性能は評価しない。** スコア間の重なりの記述に限る |

- 予測分布の不適合は、モデルの校正不足でも起きる。ラベルにしない。対象 2 は校正の評価であって、検知性能の評価ではない。
- 観測異常を価格だけで同じ時点に定義すると L3 になる。
- ラベルの閾値を絶対値にするか、その時点の尺度で割るかで有利なスコアが変わる。主の定義を A1 の計画で 1 つに固定し、他方は感度分析とする。結果を見て入れ替えない。
- 検出後のアラートと事前予測を区別する。

### 2. 時間スケールの分解

単一の「時間足」にまとめず、次を別々に定義する。

- 観測粒度(ティック、秒、分、時間、日、週など)
- スコア更新間隔
- 参照期間(基準分布を推定する過去データの長さ)
- 異常の持続時間
- 検出期限・許容遅延

観測粒度と参照期間が異なる構成を認める(例: 1 分足で毎分更新し、過去 30 日を参照する)。

### 3. 時間スケール候補

| 帯域 | 対象の例 |
|---|---|
| 超短期(ティック・秒) | 約定・気配の頻度や価格変化の急増 |
| 短期(1・5・15 分) | 急変動、短期の予測分布からの逸脱 |
| 中期(1・4 時間) | ボラティリティや市場状態の変化 |
| 長期(日・週) | 持続的なレジーム変化 |
| 超長期(月・年) | 市場構造・季節性の変化 |

長期・超長期の構造変化は、短期の条件付き予測分布に基づく検知とは別の問題になりうる。採否は §8 の規則で決める。

### 4. データ・モデルの実現可能性評価

候補ごとに、次を記録する。

- 必要な粒度・期間・サンプル数、イベント時刻の精度、欠損・休場・時刻の基準
- 既存の M1 データで評価できる範囲と、ティック・秒データの追加要件(MT5 の USDJPY ティックには 2021-11-29〜2022-02-28 の欠損がある。#914)
- 使える予測分布が**既存**か(粒度、ホライズン、更新間隔、保存先)、**新規モデル**が必要か
  - F1 の保存物は `C:\tmp\f1_run1_db0926f`(一時領域。2026-11-27 にファイルの存在を確認、中身は未照合。SHA-256 は #937)
  - 新規モデルは別の計画と承認が必要。F1〜P5 の校正の所見は引き継げない
- 長期化に伴うサンプル数・構造変化・季節性の制約

**A0 で見てよいもの。**

| 期間 | 許可 |
|---|---|
| 推定期間 | 行数、欠損、重複、時刻の基準、ラベルのイベント数 |
| 検証・評価の候補期間 | 行数、欠損、重複、時刻の基準のみ。ラベルのイベント数は数えない |
| すべての期間 | 検知スコアは計算しない |

実現可能性と検知性能の証拠を区別する。

### 5. 検知スコアと比較対象

| 系統 | 例 |
|---|---|
| 価格変動 | 絶対収益、ATR 比、移動標準偏差 |
| 統計 | 標準化残差、裾確率 |
| 確率予測 | PIT、予測分布からの逸脱・裾確率 |
| 状態変化 | 分散、自己相関、相関、活動統計の変化 |

比較相手には、適用できる範囲で次を含める。

- 単純な基準(上の価格変動の系統)。窓の長さなどの自明な変種を、検証期間で選ぶ
- 日中の時刻で調整した単純な基準(将来の変動では、持続性に次いで日中の季節性が大きいため。Phase 9a)
- ATR バケット別の経験分布
- F1 の統計モデルと DDM
- L2 のラベルでは、過去の収益と時刻を使う線形モデルと勾配ブースティング

すべて同じ時点までの情報を使う。再推定の頻度をそろえ、そろえない場合は差を結果に併記する(F1 では DDM の写像だけが固定だった)。

### 6. 評価設計

**主比較(L1・L2 のラベル)。**

- 量: 検証期間で選んだ最良の単純な基準に確率予測のスコアを**足した場合**と、基準だけの場合の、**同じ警報率での検出率の差**。
- 組み合わせ方は A1 の計画で 1 つに固定し、推定期間で当てはめる。
- 対照: 確率予測ではない第 2 のスコアを足した場合の上乗せ。
- 警報率は評価期間内のスコアの順位でそろえる(ラベルは使わない。事後的な比較であることを明記する)。過去だけで決めた閾値での検出率と実際の警報率は併記し、判定には使わない。
- 区間: 週単位のブロック・ブートストラップ。事前に固定した比較の組に対する同時区間。
- 実務上の差 δ_A は、A1 の計画で評価期間を見る前に固定する。

| 判定 | 条件 |
|---|---|
| 支持 | 上乗せの下限 > δ_A、かつ「上乗せ − 対照の上乗せ」の下限 > 0 |
| 実務上の上乗せなし | 上乗せの区間が ±δ_A 内 |
| 判定保留 | 上記以外。独立イベントが N_min 未満の場合を含む |

- **検出時刻の重なりが低いことだけでは、#896 を支持しない。**
- 副次(判定に使わない): スコア単独の比較、PR-AUC、誤警報率、検出遅延、重なり。
- 予測分布の信頼性(PIT、被覆率、裾の校正)は、検知性能と分けて報告する。
- 頑健性(記述): ニューヨーク現地時間の時間帯、市場状態、評価期間、ホライズン。
- リーク防止: 閾値・参照分布・正規化・組み合わせの推定期間と評価期間を分ける。原点より後の値を置き換えてもスコアが変わらないことを検査する。L2 は、将来区間が分割の境界をまたぐ原点を除く。

### 8. A1 対象の選定(本計画で固定)

**必須条件(すべて満たす候補だけを残す)。**

| 条件 | 内容 |
|---|---|
| M1 | L1 または L2 のラベルを定義できる |
| M2 | 推定・検証・評価の期間に、必要な粒度のデータがあり、時刻の基準が分かる |
| M3 | 評価期間の独立イベントの見込み(推定期間の発生率 × 評価期間の長さ)が N_min 以上 |
| M4 | 必要な更新間隔で、過去の情報だけから予測分布を作れる(新規モデルの場合は費用を記録する) |

**優先順位(上から順に比べる)。** (1) L1 が L2 より先、(2) 検証済みの既存の予測分布を使える、(3) 独立イベントが多い、(4) 処理するデータが少ない。

- 最初の A1 は、異常の分類と時間スケールの組を 1 つだけ選ぶ。
- 残る候補がなければ「A1 対象なし」とし、理由を記録する。これも A0 の完了とする。
- M1 を基準にした短期の検知は候補の 1 つで、他と同じ規則を適用する。優先しない。
- 選定理由、データ要件、比較相手、除外した候補と理由を記録する。日・週・月・年の状態変化は短期の検知と同じ評価設計にまとめない。

### 完了条件

- 異常の分類、操作的定義、ラベルの区分が明確である。
- 5 つの時間軸が区別され、候補と理由が整理されている。
- 各候補の実現可能性と制約が、§4 の許可の範囲で確認されている。
- 比較相手、指標、リーク防止が定義されている。
- §8 の規則を適用し、A1 の対象(または対象なし)が理由とともに決まっている。

### 注意

この登録は実験計画で、実データでの異常検知の実行や性能の主張を意味しない。F1 の未解決の原因の解明、全時間スケールの一括検証、DDM が最適なモデルであることの証明は、完了条件に含めない。A1 の実行、新規モデル、データの取得は、それぞれ別の承認が必要。
