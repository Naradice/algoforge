### 3.2 経路ごとの測定量

- **M1 の収益**: 1 足ごとの対数収益 `r_t = log(close_t / close_{t−1})`(t = 1..1,440)。
- **アトラス・マッピングと同じ定義の統計量**(最初の 1,001 終値 = 1,000 本の収益。`data.characteristics` の `compute_return_dist`、`compute_acf`、`compute_vol_clustering` をそのまま使用): std(ddof = 0)、歪度、尖度(Pearson)、acf_1・5・20、volclust_50。
- **全経路(1,440 本)の同じ統計量**と、**位置ブロック別の標準偏差**(収益 1〜100、101〜200、201〜1,000、1,001〜1,440)で初期の過渡を見る。
- **自己相関の形**: ラグ 1〜60 の自己相関(経路ごと、最初の 1,000 本)。
- **窓内(経路内)の分散比(診断用)**: `VR_win(k) = Var(Σ_{i<k} r_{t+i}) / (k Var(r))`(k = 5、20、60。**単一の経路の中で時点をずらして計算する重なりありの推定量**、最初の 1,000 本)。**経路内の時間的依存構造**を測る。**実現値側も、マッピングの使用窓(300 窓/バケット)で同じ量を計算**する(生データのみ)。
- **経路間の分散比(D2 の分解用)**: `VR_ens(c, h) = Var_paths(60h 足後の累積収益) / (60h × V_ens,M1(c))`(**異なる経路の間で累積収益の分散を計算**する)。**生成されたアンサンブルの予測分布の広がり**を測る。`V_ens,M1(c)` は、候補 c の経路の最初の 1,000 本の収益の**分散の平均**(実現値側の `V_real,M1` と同じ定義)。**同一時間範囲の変種**として、各経路の最初の 60h 本の収益の分散の平均も使う(h1・h4 を主)。
- **`VR_win` と `VR_ens` は一般に一致しない**(前者は経路内の時間的依存、後者は経路間の広がり。初期状態の分布や非定常性が違いを生む)。**両者の一致は必須ゲートにしない**。違いは、初期状態や非定常性を調べる手掛かりとして記述する。
- **混合の M1 分散**(候補間の平均の違いを含む): バケットの全経路(8 候補)の M1 収益をプールした分散 `V_ens,mix = Var_pooled(r)`(`E[候補内分散] + 候補間の平均の分散` を直接含む)。

### 3.3 分析

- **A2(A_config の検証、最優先)**: 候補ごと・バケットごとに、C3 の `V_ens,M1(first 1000)` と `σ²_atlas`(`std² + std_std_across_seeds²`)の対数比と、両者の標準誤差(経路間の標準誤差、アトラスの 5 seed の標準誤差)。std・acf_1・5・20・尖度・volclust_50 も、アトラスの候補の値(平均 ± seed 間の標準偏差)と並べる。位置ブロック別の標準偏差で、初期の過渡の有無を示す。**判定は自動化せず、差と標準誤差を表で示す**。
- **B2(M1 レベルへのショックの影響)**: C0s と C3 の M1 分散・自己相関の比(候補別・バケット別)。M2 の分解(下記 D2)の M1 レベル部分。C0s と C3 は共通の乱数系列(ショック用に別の乱数生成器)だが、観測差であり純粋なショック効果ではない。
- **C2(時間集約の直接測定。次の 2 つを区別して報告する)**:
  - **C2-a 窓内 VR の診断(経路内)**: 実現値と DDM(候補別・バケット別)の窓内 `VR_win(5, 20, 60)`、自己相関の形(ラグ 1〜60)、自己相関から導かれる理論値 `VR(k) = 1 + 2 Σ_{j<k} (1 − j/k) ρ_j` との比較。**この理論値は弱定常性を仮定した関係**であり、比較は窓内 VR の診断として扱う(不一致は非定常性・初期過渡の手掛かり)。
  - **C2-b 経路間 VR(D2 に使う)**: ホライズン別の `VR_ens(c, h)`(経路間)と、第 1 段階の `VR_real`、`VR_C3`(代理量)の比較。**窓内 VR との一致は要求しない。**
- **D2(分解の再評価。経路間 VR を使う)**: C3 の測定した混合分散 `V_ens,mix` を使って `M1' = log(√V_ens,mix / √V_real,M1)`、`VR_C3' = sd_C3² / (60h V_ens,mix)`(**経路間の分散比**)、`M3' = ½ log(VR_C3' / VR_real)`。窓内 VR は分解に使わない。**`M1' + M3' = M1 + M3`(= log(sd_C3 / sd_E1a))は恒等式なので、ゲートで確認**し、内訳(M1' − M1、M3' − M3)が代理量による値からどれだけ動くかを示す。M2 は **M2 = log(√V_C0s / √V_C3) + ½ log(VR_C0s / VR_C3)**(M1 レベルの寄与と集約の寄与)に分ける。分解は代数的であり、因果の識別ではない。
- **E2(最上位バケットの反転)**: バケット 19 で、候補別の `VR_ens(c, h)`、自己相関の形(長いラグで正か)、尖度、volclust、(delta, wma)。どの候補が分散比を 1 以上にするかを示す(記述のみ)。バケット 0・8・15 と比較する。**解釈上の注意**: ボラティリティ・クラスタリング(絶対収益の自己相関)だけでは、累積収益の分散比が 1 を超えることを直接説明できない。分散比には**収益の自己共分散**が関係するため、まず ACF(符号つきの収益の自己相関)の形と、経路内(`VR_win`)・経路間(`VR_ens`)の違いを確認する。

## 4. 事前ゲート(失敗したら停止して報告)

1. **入力・コードの同一性**: 生データのハッシュ、第 1 段階の保存値(P5-B のゲート 1〜6)の再現、`p3_sim.py`・`ddm_simulator.py`・`f1_ddm.py` が F1・P3 の実行コミットと同一(改行の差を除く)。
2. **ビット単位の再生成の一致**: 再生成した**成功経路 8,000 件の全件**について、`cum_returns(win)` が保存済みの `ens[q, :, k]`(試行 ID から対応する経路 k)と**厳密に一致**(`np.array_equal`)。**1 件でも不一致なら停止し、原因を調査**する(乱数・並列・スレッド数などの影響を含めて)。
   - **失敗試行の扱い(範囲を固定)**: 保存された記録(`C3_seed1.json`、`C0s_seed1.json` の `info`)では、対象の 8 セル(バケット 0・8・15・19 × C3・C0s)はすべて `attempts = successes = 1,000`、すなわち**失敗試行が 0 件**。したがって、**再生成するのは試行 0〜999 のちょうど 1,000 回/セル(計 8,000 回)だけで、失敗試行の再生成は行わない**。再生成の途中で、保存された成功試行が `None`(失敗)になった場合は不一致として停止する。ゲートの「失敗の再現」は、記録上の失敗試行が 0 件であることの確認(`attempts = successes`)に限る。
   - **C3 の一致ゲートに失敗した場合は C0s へ進まず、原因を報告して停止する。**
3. **並列の独立性**: 小さい部分集合(各バケット・各条件 8 経路、計 64 経路)を、ワーカー 1 と 18 で再生成して、結果が厳密に一致する。この検査の追加計算は 64 回の再生成以内。
   - **再生成の総数の上限**: 本番 8,000 回 + 並列検査 64 回 = **8,064 回以内**(約 30〜35 分の見込みの上限)。これを超える追加の生成はしない。
4. **統計量の定義の同一性**: 測定に使う統計量の関数が `data.characteristics` のものと同一で、既知の合成系列で numpy の参照実装と一致する(窓内 `VR(k)` と自己相関の実装を含む)。マッピングの使用窓 20 窓で、`real_stats` を再現する(第 1 段階のゲートの再利用)。
5. **分解の恒等性**: `M1' + M3' = M1 + M3`(1e-12)、M2 の分割の和が M2 と一致(1e-12)。
6. **保存**: 再生成した終値のファイルごとの SHA-256 のマニフェストを作成し、再読み込みで同じ統計量が得られることを確認する。
